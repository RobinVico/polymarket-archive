用户 2026-07-08 对全自动项目 ([[full-auto-account-plan]]) 明确要求: "你加的每一步都要先跟我说, 不要一次性全加, 很容易乱"。同轮他还否掉了我提的复杂进场闸 (edge 门槛/GLM双跑一致/信心分流/流动性检查): "筛选程序规则写死, 不要太麻烦, 你这些现在的都不用"。

**Why**: 他要全程掌控节奏和可理解性; 复杂机制他看不懂就等于失控。

**How to apply**: ① 每个 pipeline 步骤 = 先用大白话讲这一步做什么/花不花钱/动不动钱 → 得到明确同意 → 实现+实测 → 汇报结果 → 提出下一步 spec 再等点头。② 规则设计首选"一条写死的简单线" (如 0.40<价<0.85), 不擅自加聪明逻辑; 想加保护先问。③ 新代码尽量放独立新文件 (如 auto_scheduler.py), 不改同步自老项目的模块, 保持以后规则同步零冲突。
