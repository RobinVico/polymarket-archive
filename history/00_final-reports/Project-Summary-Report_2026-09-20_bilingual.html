1. What this project is (one-sentence version)一、这个项目是什么（一句话版）

A trading bot that uses AI (first Claude via manual prompt-pasting, later Zhipu GLM fully automated) to discover, buy, monitor and exit positions on Polymarket prediction markets. It evolved from "human decides, bot only executes take-profit/stop-loss" semi-automation all the way to a fully autonomous scan→discover→buy→re-evaluate→exit pipeline, finally running three live-money accounts as a controlled experiment on three exit strategies, and was sealed on 2026-09-20.

用 AI（先 Claude 人工贴、后智谱 GLM 全自动）在 Polymarket 预测市场上选品、下单、盯盘、止盈止损的交易机器人。项目从「人做决定、机器人只执行止盈止损」的半自动，一路演进到「扫描→AI 选品→自动下单→自动重评→自动出场」的全自动，最后同时跑三个真钱账户做三种策略的对照实验，于 2026-09-20 封存。

Four stages (incl. prehistory) + one side line:
⓪ Prehistoric v1 "polymarket-bot" (2026-04-08 ~ 04-16): the earliest attempt — browser automation driving Gemini Deep Research for discovery; v2 survives only as a technical document.
① v3 semi-auto initial (2026-04-27, finalized and frozen within a day): human places orders; the bot only runs tiered take-profit/stop-loss.
② Semi-auto main project v4 → v7.5.4 (2026-05-09 ~ 07-24): human pastes prompts to Claude and makes the calls, bot executes; 132 substantive commits; the stop-loss / take-profit / re-evaluation system matured here.
③ Fully-automatic AUTO v8.0 → v8.5.5 (2026-07-06 fork ~ 2026-09-01 API stop): zero-human pipeline, GLM takes over all analysis; later expanded into the three-account experiment.
➕ Side line: Weather bot (since 2026-07-12, own wallet) — deterministic arbitrage on Polymarket daily-max-temperature markets (after sunset the temperature only falls; buy the 0.90–0.995 bucket for a 1–5% edge), fully isolated from the main line.

③ 全自动 AUTO v8.0 → v8.5.5（2026-07-06 fork ~ 2026-09-01 停 API）：零人工全流水线，GLM 全面接管分析；后期扩成三账户对照实验。

The most valuable findings of the whole experiment (from the three-account control):
1️⃣ Exit rules are everything. On the same batch of GLM recommendations, the main account with full take-profit/stop-loss lost only 9.1%, while the two bare-hands control accounts each lost 54–56%. The money saved came from exit discipline, not from market selection.
2️⃣ GLM's discovery is a disaster in the low-price range. Bench's dual ledger (stop-losses don't pollute accuracy) measured 56.8% overall accuracy (83/146), but <20¢: 1/14 and 20–40¢: 10/31 — low-price long shots were systematically overrated ("12 bets, 0 hits under $0.30" was the verbatim July–August finding). The 40–80¢ band, at ~70% accuracy, was the only usable range.
3️⃣ Small positions are uneconomical. At $2–5 per position, order rounding, spread and unsellable dust eat any edge a strategy could have.
整个实验最值钱的结论（三账户对照给出的）：
1️⃣ 出场规则就是全部。同一批 GLM 推荐，配上完整止盈止损的主账户只亏 9.1%，裸拿的两个对照账户各亏 54~56%。赚（少亏）的钱来自止盈止损纪律，不是来自选品。
2️⃣ GLM 的选品在低价区是灾难。Bench 双台账（止损不污染准确率）实测：整体判对率 56.8%（83/146），但 <20¢ 区间 1/14、20-40¢ 区间 10/31——低价长尾被严重高估，「≤$0.30 区间 12 投 0 中」是 7-8 月复盘的原话。40-80¢ 区间判对率约 70%，是唯一能看的区间。
3️⃣ 小仓位不经济。$2~5 的仓位下，买单凑整、点差、卖不掉的废仓等磨损占比放大，策略再好也难覆盖。

3. What each stage did三、各阶段分别干了什么

Stage ⓪ — Prehistoric v1 "polymarket-bot" (2026-04-08 ~ 04-16)阶段⓪ 史前 v1「polymarket-bot」（2026-04-08 ~ 04-16）

The origin of everything: an "Autonomous Polymarket Bot" that drove Gemini Deep Research (and briefly Claude's web UI) through browser automation to research candidate markets and emit structured trade recommendations, targeting mispriced low-probability events. It left behind complete code, a full backup from Apr 15, two dedicated Chrome profiles and a directory full of debug screenshots (the pain of automating web UIs). The "free-of-API-fees, drive-the-web-version" route was abandoned in favor of v3's paste-the-prompt semi-automation — but the core shape, "AI deep research + structured JSON recommendation", survived from here to the very end. v2 never had its own directory; only a technical document remains (in archive folder 05).

整个项目的起点：「Autonomous Polymarket Bot」，思路是用浏览器自动化去驱动 Gemini Deep Research（也试过 Claude 网页版）对候选市场做深度调研、输出结构化交易建议，主打错价的低概率事件。留下了完整代码、04-15 的全量备份、两个配套 Chrome profile 和满目录的 debug 截图（自动化网页 UI 的辛酸史）。这条「免 API 费、走网页版」的路线后来被放弃，转向 v3 的「人贴 prompt」半自动——但「AI 深度调研 + 结构化 JSON 建议」的核心形态从这里一直延续到最后。v2 没有独立目录存世，只留下一份技术文档（在档案 05 文件夹）。

Stage ① — v3 semi-auto initial (2026-04-27, frozen)阶段① v3 半自动初版（2026-04-27，冻结）

Design philosophy: human–machine division of labor. Scanner mechanically filters liquidity/price/depth into a scan report → human takes it to Claude Research for analysis and places limit orders on the website (as maker, saving taker fees) → bot watches every 3 minutes, executing T1/T2/T3 tiered take-profit and W1/W2/W3 reverse stop-loss → a yellow alert prompts a human re-evaluation near targets. Frozen after two commits; the prototype for everything that followed.

设计哲学是「人机分工」：Scanner 机械筛选流动性/价格/深度出扫描报告 → 人拿报告去 Claude Research 做分析、人自己在网页下限价单（做 maker 省手续费）→ bot 每 3 分钟盯盘，执行 T1/T2/T3 分层止盈和 W1/W2/W3 反向止损 → 接近目标时黄色提醒人去重评。两次提交后即冻结，作为后续一切的原型。

Stage ② — Semi-auto main project v4 → v7.5.4 (2026-05-09 ~ 07-24)阶段② 半自动主项目 v4 → v7.5.4（2026-05-09 ~ 2026-07-24）

The project's main battleground — live money, 132 substantive commits (plus 3,200+ automated cron-backup commits). Human pastes DISCOVERY/REEVAL prompts to Claude and decides; bot scans, monitors, auto-executes take-profit/stop-loss, keeps books, serves the web dashboard. The core assets matured here:

项目的主战场，跑真钱、132 次实质提交（外加 3200+ 次 cron 自动备份提交）。人负责把 DISCOVERY/REEVAL prompt 贴给 Claude、拍板买卖；bot 负责扫描、监控、自动止盈止损、记账、网页面板。核心资产在这里成型：

  • Decision engine: 3-tier stop-loss (convergent/hybrid/event-driven, LLM entry classification), asymmetric trigger pricing (TP uses best_bid against phantom highs, SL uses cur against transient fakes), trailing stops, 2×-sell-all take-profit ladder.
  • Re-evaluation system: blind-evaluation-first methodology, pre-crash anchor de-biasing, GLM takeover (glm-5.2 + search_pro + max thinking + regex fallback), emergency API pause switch.
  • Infrastructure: SQLite WAL, dashboard (equity curve / event center / historical position analytics / mobile read-only view), auth & rate limiting, paper trading, DNS-poisoning guard, dual-repo sanitized publishing, cron auto-backup.
  • 决策引擎：三档止损 tier（收敛/混合/事件型，LLM 入场分类）、不对称触发价（止盈用 best_bid 防虚高、止损用 cur 防瞬时假象）、移动止损、翻倍全卖等止盈梯队。
  • 重评体系：盲评优先方法论、大跌前中枢反锚定、GLM 接管重评（glm-5.2 + search_pro + thinking max + 正则兜底）、API 紧急暂停开关。
  • 基础设施：SQLite WAL、Dashboard（资产曲线/事件中心/往期仓位分析/手机只读版）、鉴权与限流、测试仓 paper trading、DNS 污染防护、双仓脱敏发布、cron 自动备份。

On 2026-07-24 the old bot was killed by user decree and its account repurposed as the AUTO project's Bench control account; this directory froze there.

2026-07-24 老 bot 被用户拍板杀掉，该账户转为 AUTO 项目的 Bench 对照账户，此目录就此定格。

Stage ③ — Fully-automatic AUTO v8.0 → v8.5.5 (2026-07-06 ~ sealed)阶段③ 全自动 AUTO v8.0 → v8.5.5（2026-07-06 ~ 封存）

Forked 2026-07-06 from semi-auto v7.4.3 as an independent copy (own account/database/port 5052/version line), targeting "fully automatic, zero human". Development protocol: one step at a time with user sign-off, simple hard-coded rules, all new code in standalone new files so future syncs from the old project never conflict. A two-day sprint (07-06~08) opened the whole pipeline:

2026-07-06 从半自动 v7.4.3 fork 出的独立副本（独立账户/数据库/端口 5052/版本线），目标「全自动交易，零人工」。开发协议：一步一报、规则简单写死、新代码只放独立新文件保证与老项目同步零冲突。两天冲刺（07-06~07-08）打通全流水线：

  • Full pipeline: scheduled scans 09:00/21:00 (27 whitelisted tags) → streaming GLM discovery (feed-as-you-scan, 4-way concurrency, multi-round agentic search) → hard-coded routing (0.40<price<0.85 real money, else paper) → auto ordering (Kelly sizing + confidence multiplier + drift re-check) → monitoring → dip-triggered + daily 15:00 GLM re-evaluation → auto exit.
  • New-account battle: Polymarket's 2026 deposit-wallet architecture requires sig=3 + vendored client 1.0.2 + integer-share rounding — an afternoon of pain; the live-money round trip verified at a total cost of 3 cents.
  • Safety gates: universe iron rule (only whitelist-tag scanned markets tradable, born of the 07-08 sports mis-buy incident), anti-self-hedge lock, direction-sanity re-ask gate, no-metadata-no-re-eval, 16 fixes from a full code audit.
  • Strategy iteration (dense mid-late July): event-driven −50% hard stop, convergent/hybrid breach → direct sell, exit-guard removal, q-calibration moved from prompt (×0.5) to Python (×0.8), per-position cap $15→$5, monthly drawdown budget removed (see timeline).
  • Three-account experiment (built 07-23~24): Bench baseline (takes everything, measures GLM's raw accuracy) + Shadow low-price hold (−60% stop derived from a drawdown study of 18 low-price positions), each with its own dashboard.
  • Endgame: during the 08-12~08-27 outage window Zhipu silently changed its Web Search API (ignores count, always returns 50 items) → on resume, context doubled, discovery kept hitting the 20-minute circuit breaker, bills doubled → 09-01 user ordered all paid APIs stopped (v8.5.5), leaving only free price-based monitoring → sealed 09-20.
  • 全自动流水线：每天 09:00/21:00 定时扫描（27 个白名单 tag）→ GLM 流式选品（扫一个喂一个、4 路并发、多轮自主搜索 agent）→ 写死规则分流（0.40<价<0.85 真买，否则测试仓）→ 自动下单（Kelly 仓位 + 信心乘数 + 漂移复核）→ 盯盘 → 大跌触发 + 每日 15:00 全仓 GLM 重评 → 自动出场。
  • 新账户攻坚：Polymarket 2026 新架构存款钱包必须 sig=3 + vendored client 1.0.2 + 整数股数凑单——折腾一下午的答案，真钱闭环全程磨损 3 分钱验证通过。
  • 安全闸门：宇宙铁律（只交易白名单 tag 扫描报告里的市场，源于 07-08 体育误买事故）、防对锁、方向纠错反问闸、无档案仓不重评、16 项全代码审查修复。
  • 策略迭代（7 月中下旬密集调参）：事件型 −50% 硬止损、收敛/混合砸穿直接平仓、exit 护栏删除、q 校准从 prompt 五折改 Python 八折、单仓硬顶 $15→$5、月回撤预算删除等（详见时间线）。
  • 三账户实验（07-23~24 搭起）：Bench 基准（照单全收测 GLM 裸预测）+ Shadow 低价拿到底（−60% 止损来自 18 条低价仓回撤研究），各配独立监控页。
  • 收尾：08-12~08-27 停机窗口里智谱偷偷改了 Web Search API（无视 count 恒返 50 条）→ 复跑后 context 翻倍、选品频繁撞 20 分钟熔断、账单翻倍 → 09-01 用户令停掉全部付费 API（v8.5.5），只留免费盯盘和止损守仓 → 09-20 封存。

5. Final architecture at a glance (plain words)五、系统架构终版一览（大白话）

  • One process, three accounts: autobot.py (port 5052) runs the main strategy + Bench + Shadow as isolated instances — separate keys/funds/tables, a same-credentials guard prevents cross-wiring.
  • Discovery chain: scheduled scans over 27 whitelisted tags (medium filter) → tags with ≥5 candidates go to GLM (discovery key) → GLM's multi-round search yields JSON recommendations → 0.40~0.85 buys real money (quarter-Kelly on a frozen $50 reference + confidence multiplier + $1~5 hard bounds), the rest go to free paper → Bench takes everything, Shadow takes the ≤0.40 half.
  • Guarding chain (pure price logic, zero API, still running at seal): convergent 20% off peak (12% if ≤3 days), hybrid 35%, event-driven −50% hard stop + $0.05 floor, confirmed over consecutive ticks then sold directly; take-profit ladder 2×-sell-all / 0.92-sell-half etc.
  • Re-evaluation chain (stopped): event-driven ≥5pp-from-best triggers once + daily 15:00 sweep; GLM primary with Claude as outage fallback; direction-sanity re-ask gate against flipped numbers.
  • Pages: main dashboard (equity curve / daily reports / event center) + /auto candidates + /paper + /history + /bench + /shadow + mobile /m.
  • Safety design: universe gate (whitelist tag + scan-report double check), blacklist paper-only, anti-self-hedge, 3pp pre-order drift check, DNS-poisoning guard, pending-row-first crash-safe ordering.
  • 一个进程管三个账户：autobot.py（端口 5052）里跑主策略 + Bench + Shadow 三个隔离实例，各自的私钥/资金/表互不可见，同凭据守卫防止配串。
  • 选品链：定时扫描 27 个白名单 tag（medium 档）→ 每个 tag 候选 ≥5 才送 GLM（选品 key）→ GLM 多轮搜索后出 JSON 推荐 → 价格 0.40~0.85 真买（Kelly $50 冻结本金 + 信心乘数 + $1~5 硬边界），其余进免费测试仓 → Bench 照单全收、Shadow 只吃 ≤0.40 的那半。
  • 守仓链（纯价格逻辑，零 API，封存时仍在跑）：收敛型峰值回撤 20%（≤3 天 12%）、混合型 35%、事件型 −50% 硬止损 + $0.05 地板，连拍确认后直接平仓；止盈翻倍全卖/0.92 卖半等梯队。
  • 重评链（已停）：事件型从最好点回撤 5pp 触发一次 + 每日 15:00 全仓巡检；GLM 重评 key，Claude 只作故障兜底；方向纠错反问闸防数字填反。
  • 页面：主页监控（资产曲线/按天战报/事件中心）+ /auto 候选 + /paper 测试仓 + /history + /bench + /shadow + 手机版 /m。
  • 安全设计：宇宙闸门（白名单 tag + 扫描报告双重验证）、黑名单只进测试仓、防对锁、临下单 3pp 漂移复核、DNS 污染防护、pending 先落库防崩溃重复买。

7. If ever restarted — what to improve (by priority)七、如果以后重启，还能改什么（按优先级）

  1. Fix the 50-item search problem (prerequisite for re-enabling APIs): don't wait for upstream — truncate results client-side to 15 items before feeding GLM. One small change, already scoped.
  2. Feed Bench data back into discovery: the measurements already point the way — below 40¢ accuracy was 11/45, so ban or heavily down-weight that range; the ~70%-accurate 40–80¢ band is the only edible one. The 0.40~0.85 routing line accidentally blocked the worst range, and the Shadow experiment proves "hold cheap long shots to the end" doesn't work.
  3. Calibrate q from data: AUTO_Q_TRUST=0.8 was a guess. 146 resolved Bench samples are enough to regress a "GLM-reported q vs. realized win rate" calibration curve.
  4. Position-size economics: at $2–5, rounding/spread/dust friction dominates. Either scale bankroll so positions are ≥$20, or accept that the cost structure fails at small size.
  5. Upstream API behavior assertions: alarm on result counts, token usage and per-round latency; auto-pause the money-burning chain on anomaly (this time 13 breaker hits burned for half a month before being noticed).
  6. Dust-position module: fix the infinite 30s sell-retry in a standalone new file (monitor.py untouchable per the isolation rule), with backoff + forced write-off of dust.
  7. Automatic ledger reconciliation: compare ledger totals against asset truth daily; red-alert past a threshold instead of discovering the gap in a month-end post-mortem.
  8. Multi-model comparison: the whole experiment tested only GLM. The Bench framework is ready — plug in a second model (Claude/DeepSeek/…) on the same markets to separate "AI can't do this" from "GLM can't do this".
  9. Notifications / watchdog: user chose to go without (checks the dashboard personally). For true unattended operation, a dead process with nobody knowing is the hard flaw.
  10. Longer experiment window: only ~2 months of genuine three-account operation (minus a half-month outage); 146 resolved samples across 5 price buckets is thin.
  1. 修智谱搜索 50 条问题（恢复 API 的前提）：不等上游，客户端拿到结果自己截断 items 到 15 条再喂 GLM。修法已明确，一处小改。
  2. 用 Bench 数据反哺选品：实测数据已经指明——低价区（<40¢）判对率 11/45，应直接禁买或大幅降权；40-80¢ 判对率 ~70% 才是能吃的区间。现在的 0.40~0.85 分流线歪打正着挡掉了最差区间，但 Shadow 实验证明低价「拿到底」策略整体不成立。
  3. q 校准系数用数据定：AUTO_Q_TRUST=0.8 是拍的。146 条已结算的 bench 样本足够回归一条「GLM 报的 q vs 实际胜率」校准曲线，代替拍脑袋。
  4. 仓位经济学：$2~5 仓位下凑整/点差/废仓磨损占比太大。要么本金上量让单仓 ≥$20，要么承认小资金下该策略成本结构不成立。
  5. 上游 API 行为断言：对搜索返回条数、token 用量、单轮耗时设告警线，异常自动暂停烧钱链路（这次 13 次熔断烧了半个月才被发现）。
  6. 废仓处理模块：卖不掉的仓无限重试问题要修得开独立新文件（monitor 按铁律不能改），加退避 + 尘埃仓强制核销。
  7. 台账自动对账：每日把逐笔台账合计和资产真相对一次，差额超阈值上红色警示，别等月末人肉复盘才发现高估。
  8. 多模型对照：整个实验只测了 GLM 一家。Bench 框架现成，接入第二家模型（Claude/DeepSeek 等）跑同一批市场，才能分清「AI 不行」还是「GLM 不行」。
  9. 通知渠道 / watchdog：当初用户拍板不做（自己定期看盘）。真要长期无人值守，进程死了没人知道是硬伤。
  10. 更长实验周期：5 个月里真正三账户并跑只有 ~2 个月且中间停机半个月，样本量（146 条结算）对 5 个价位桶来说仍偏薄。
