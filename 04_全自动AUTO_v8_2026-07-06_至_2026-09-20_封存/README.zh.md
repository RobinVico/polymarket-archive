## 全自动闭环

```
09:00 / 21:00(本机时间)
    │
    ▼
┌─────────────────────────────────────────────────────────────────────┐
│  流式"扫一个喂一个",4 路并发                                          │
│  对每个白名单 tag:当场重扫 → ≥5 候选门槛 → 喂 GLM                     │
│  (每个 tag 在丢给 GLM 那一刻用的是最新盘口,不吃旧数据)               │
└─────────────────────────────────────────────────────────────────────┘
    │  每个 tag 一完成就立刻写候选
    ▼
┌─────────────────────────────────────────────────────────────────────┐
│  即时执行(生产者/消费者)                                            │
│  一出推荐就立马下单,其他 tag 继续分析                                 │
│  分流:  0.40 < 现价 < 0.85 → 真买(¼-Kelly 金额)                    │
│          否则                → 测试仓(paper)                        │
│  每笔下单串行 + 宇宙闸门 + 临下单漂移复核                              │
└─────────────────────────────────────────────────────────────────────┘
    │
    ▼
  盯盘(30s)  ──►  移动/分档 止损 + 止盈
    │
    ▼
  每日 15:00 全仓巡检 + 大跌触发重评  ──►  GLM 决策
    │                                       hold / update_q / exit
    ▼
  离线自动执行(真钱)
```

全程无人值守。LLM 层用**智谱 GLM**(两把 key 按角色分工);Claude 仅在 GLM 失败时兜底。

## 核心规则(全是用户拍板、写死的)

- **宇宙铁律** —— 只交易「白名单 tags 扫描报告里真实出现的市场」(双闸门:tag∈白名单 **且** slug 在该 tag 报告里)。挡幻觉/注入的市场。
- **分流** —— `0.40 < 现价 < 0.85` → 真买,否则测试仓。没有其他闸门。
- **≥5 候选门槛** —— 一个 tag 扫出的候选 <5 个就不送 GLM(省 API)。
- **重评** —— 每日 15:00 全仓巡检(4 路并发)+ 大跌触发;无档案仓一律不重评(改成红色告警)。
- **不设额度** —— 无日限额、无持仓数上限(单仓金额由 ¼-Kelly 计算器管:cluster 上限 + 月回撤预算,硬边界 [$1, $15])。
- 两把智谱 key 绝不混用 · tags 永远不变 · 不设亏损熔断 / 不做通知 / 不做 watchdog(有意为之)。

## 账户架构

本账户走 Polymarket 2026 **存款钱包**新架构,**必须 `POLY_SIGNATURE_TYPE=3`(POLY_1271)** —— sig=0/1/2 一律余额 `$0` 且报 `maker address not allowed`。仓库根 vendored `py_clob_client_v2` **1.0.2**(不 pip 装;别降回 1.0.0,它给 sig=3 签名错)。

## 运行

```bash
cp .env.example .env      # 填凭据(见下)
bash restart.sh           # 唯一推荐的启动/重启(只杀 :5052 LISTEN 进程、跑 autobot.py)
tail -f bot.log
```

`.env` 必填:`POLY_PRIVATE_KEY`、`POLY_FUNDER`、`POLY_SIGNATURE_TYPE=3`、`ZHIPUAI_API_KEY_DISCOVERY`、`ZHIPUAI_API_KEY_REEVAL`、`DASHBOARD_PASSWORD`、`FLASK_SECRET_KEY`。完整配置、可调 env、运行规则见 **`CLAUDE.md`**;架构与策略细节见 **`技术报告.md`**。
