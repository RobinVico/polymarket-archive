## 二、全自动流水线(端到端)

一句话:**定时扫描 → 流式"扫一个喂一个"4 路并发 GLM 选品 → 写死分流 → 有推荐就立马下单(其他继续分析)→ 盯盘 → 定时+大跌重评 → 离线自动出场。**

### Stage A — 定时扫描调度(`auto_scheduler.py`)

- 常量 `SCAN_HOURS=(9,21)`、`CHECK_EVERY_SEC=60`。`start_scheduler()` 起一个守护线程跑 `_loop()`。
- 每 60s `_current_slot()` 算出当前 slot 字符串 `'YYYY-MM-DD HH:00'`(= 最近一个已到点的扫描时刻;今天还没到第一个点则归昨天最后一个)。
- slot 标记存 `app_state.auto_scan_last_slot`:**重启不重放**已跑过的 slot,**停机错过的 slot 开机补跑**。本 slot 扫描失败不重试,等下一个 slot。
- 同一心跳还带动 `auto_daily_reeval.maybe_run()`(Stage F)。调度器**单线程串行** —— 扫描拖太久会让日巡检晚点,但不丢。

`_run_scan(slot)` 编排**生产者-消费者**:

1. 起消费者线程 `auto_trader.run_execution_consumer(slot, stop_exec)`(daemon)。
2. 跑生产者 `auto_discovery.scan_and_discover_stream(slot)`(阻塞到所有 tag 处理完)。
3. `finally`: `stop_exec.set()` → `consumer.join(timeout=180)`。
4. 收尾兜底 `auto_trader.execute_for_slot(slot)`:幂等(已执行的候选不再是 `'new'`),也是消费者线程若启动失败时的唯一执行入口。

### Stage B — 流式"扫一个喂一个" 4 路并发选品(`auto_discovery.py`)

- 入口 `scan_and_discover_stream(scan_slot, tier_filter=(1,2), mode="medium")` → 非阻塞抢 `_disc_lock`(RLock,跟定时轮/手动 `discover_now` 互斥防重复烧 GLM)→ `_scan_and_discover_stream_locked`。
- 取 tier 1+2 全部 tag(`tags.list_tags_by_tier()`),manifest 全置 `pending`,然后 `ThreadPoolExecutor(max_workers=STREAM_CONCURRENCY)`(默认 **4**,`AUTO_DISCOVERY_CONCURRENCY`)对每个 tag 跑 `_stream_process_tag`。
- **每个 tag 的一路**:
  1. **当场即时重扫这个 tag**(`scanner.scan_by_tag(tag, mode="medium")` → 写 `{slug}.md` → 更新 manifest)。**这就是整套设计的核心**:每个 tag 在丢给 GLM 的那一刻用的是最新盘口;排在慢 tag 后面的 tag 不会吃十几分钟前的旧价。
  2. 数候选 = 报告里 `### ` 开头的行数。**≥5 候选门槛**:`n < MIN_CANDIDATES`(默认 5)→ 跳过并记日志(绝不静默,死规则 9);未配 key → `scan-only`。
  3. 过门槛 → 立刻喂 GLM(`_run_tag_locked`)。
- `_run_tag_locked`:组 prompt(`DISCOVERY_PROMPT` + cluster 字典 + 机器可读 `JSON_APPEND`)→ 先试**多轮自主搜索** `auto_glm_agent.agentic_analyze`(若开),**任何异常回退**到老的一次性注入 `web_search` → `_extract_recs`/`_normalize` 解析校验(百分比归一、side∈{YES,NO}、0<price/q<1、tier/confidence 白名单)。**追问规则**:无推荐**且**不是合法空数组 → 追问**恰好一次**;合法 `[]` = 正经"无推荐",不追问(死规则 2)。入库 `auto_candidates`(按 `(scan_slot,slug,side)` 去重,每条打 `route_of(cur_price)` 标签)+ 一条 `auto_discovery_runs`(tokens/无效数/是否追问/错误)。
- 老的批量路径 `run_for_slot`/`run_tag` 保留给手动用(`POST /api/auto/discover_now`,body 可 `{"tag":"..."}`;手动单 tag 不受 ≥5 门槛限制)。页面 `/auto` + `GET /api/auto/candidates`。

### Stage B′ — GLM 自主搜索代理(`auto_glm_agent.py`)

`agentic_analyze(...)` 把 `web_search` 变成**可调用的函数工具**并循环:模型发 `tool_calls(query)` → 打智谱 REST `/paas/v4/web_search`(`search_pro`)→ 精简结果回喂 → 再想再搜 → … → 最终文本。上限 `MAX_SEARCHES=8`、`SEARCH_COUNT=15`/次、`max_tokens=65536`。**任何失败抛 `AgentError`**,调用方(选品**和**重评)回退到一次性注入 —— 定时链路永不卡死。`AUTO_GLM_AGENTIC=0` 整体关闭。

### Stage C — 写死分流(`auto_discovery.route_of`)

`ROUTE_REAL_MIN=0.40`、`ROUTE_REAL_MAX=0.85`。`route_of(p)` → `"real"` 当且仅当 `0.40 < p < 0.85`,否则 `"paper"`(恰好等于边界 → paper)。**没有其他任何闸门**。分流按**执行时刻的新鲜 ask** 重新计算,不是推荐价。

### Stage D — 即时执行(生产者-消费者)(`auto_trader.py`)

- `run_execution_consumer(scan_slot, stop_event, poll_s=3.0)`:每 ~3s 调一次 `execute_for_slot(scan_slot)`。4 个分析线程**只写候选**,这个消费者线程一发现新候选就立刻执行。因为执行会把候选 `status` 标离 `'new'`,后续轮询和收尾只捡真正没执行的 → **不双买**。`stop_event` 置位后做最后一次执行再退出。分析线程从不调用执行 → **下单再慢也绝不阻塞分析**。
- `execute_for_slot` → `_run_lock.acquire(blocking=False)`(普通 Lock,所以消费者、收尾、手动 `/api/auto/execute_now` 三者的**下单全程串行**)→ `_execute_for_slot_locked`。

  1. **TTL**:`created_at` 超 `CANDIDATE_TTL_H`(24h)→ `expired`。
  2. **轮内去重** `(slug, side)`。

  5. **防对锁**:已持有同市场任一其他 token → 拒买;**并触发 `_trigger_reverse_reeval`**(第五章)。
  6. `_fresh_ask(token)` → `route_of(fresh)`:
     - **paper**:同 token 已有未平仓测试仓则跳,否则 `POST /api/paper/add`(`auto_size`,`fallback_usd=5`)→ 标 `paper`。测试仓进去后零操作(死规则 4)。
     - **real**:`MAX_POSITIONS` 检查(0=不限)→ `GET /api/suggested_size`(¼-Kelly `position_size_usd` 计算器)→ <$1 跳 → `DAILY_CAP_USD` 检查(0=不限)→ **临下单漂移复核**:重取 `ask2`,若 `|ask2−fresh|·100 > MAX_DRIFT_PP`(3pp)或漂出 40~85 → 放弃(死规则 10)→ `POST /api/buy_position` → 从 `"≈ $X.XX"` 消息解析**实际成交额**入台账(而非请求额)→ 等最多 6×10s 仓位同步拿真实 avg → `POST /api/record_position`(**重试 3 次**,cluster_id 不含 `'-'` 置空防端点整条拒)。标 `bought`,或录档失败 → `bought(meta失败⚠️裸奔)` + 红色 `no_meta_alert` 事件。发 `auto_buy` 事件。

## 四、决策引擎(止盈 / 止损)—— 继承自老项目 7.4.5

> `monitor._evaluate_position()`,第一个匹配的优先级胜出。**$0.05 地板永远第一、无条件**兜底。

### 4.1 优先级阶梯

| 优先级 | 状态 | 触发(用哪个价)| 动作 |
|---|---|---|---|
| 0 | `NO_META` | 无档案 | 跳过 |
| 1a | `TAKE_PROFIT`(分档)| **best_bid** | 见 4.2 |
| 1b | `TAKE_PROFIT_PNL` | (best_bid−avg)/avg ≥ +100% | 全卖 |
| 2 | `STOP_LOSS`(分档)| **cur_price**(地板除外)| 移动/锚/地板,见 4.3 |
| 3 | `TIME_STOP` | ≤2 天结算 **且** \|cur−entry\|<5pp | 自动全卖 |
| 4 | Edge-based | `edge=q−cur` | 子状态,见 4.7 |

### 4.2 止盈阶梯(分档)

- **event_driven**:"翻倍先到 vs 0.92 卖半,谁先谁执行"。
  - `(bid−avg)/avg ≥ +100%`(仅当入场 <~$0.46 时 2×avg<0.92)→ **全卖**锁翻倍。
  - 否则 `best_bid ≥ 0.92`(`TAKE_PROFIT_PRICE_EVENT_DRIVEN`)→ **卖半**(`TAKE_PROFIT_HALF_FRACTION=0.5`,标 `tp_half_sold`)。event_driven **永不走通用 0.90 全卖**(否则留的半仓被秒卖)。
  - **半仓保护**:卖半后留的那半 `best_bid < 0.782`(=0.92×0.85)→ 全卖余量(`TAKE_PROFIT_HALF_PROTECT`)。
- **convergent 且 ≤3 天结算**:`best_bid ≥ 0.88`(`TAKE_PROFIT_PRICE_CONVERGENT_NEAR`)→ 全卖。
- **其余**:`best_bid ≥ 0.90`(`TAKE_PROFIT_PRICE`)全卖,或 +100% 翻倍全卖。

部分卖出:成功卖半 → 标 flag + `save_closed_position(size=half)`,但**绝不 `clear_position_meta`**(余量继续管);失败 → 不标不清,下拍重试。

### 4.3 止损三档 + 移动止损机制

| 档 | 机制(现行)| 常量 / 值 |
|---|---|---|
| `convergent` | **从 peak 回撤** ≥ 20%;≤3 天结算用 12%;连 **6 拍**确认(反弹归零)| `TRAILING_STOP_PCT_CONVERGENT=0.20` / near 0.12 |
| `hybrid` | **从 peak 回撤** ≥ 35% + 6 拍确认(7.4.4 从固定 −35% 改成移动)| `TRAILING_STOP_PCT_HYBRID=0.35` |
| `event_driven` | **−50% 强行止损【直接平仓】**(AUTO 8.1.0;早于重评/护栏/关止损、任何东西越不过)+ `$0.05` 地板 | `EVENT_DRIVEN_HARD_STOP_PCT=0.50`(原 `..._BY_TIER["event_driven"]=0.60`→交重评 已作废)|
| 未分类 | **默认当 hybrid**(弃用 legacy −25%)| `STOP_LOSS_PCT_LEGACY=0.25` 仅老行兼容 |

- **peak 跟踪**:`position_meta.peak_price` 每拍 `max(old,cur)`(持久化 + 内存)。
- **砸穿后路由**(AUTO 8.3.0 起**全部直接平仓,`PENDING_REEVAL` 退役**):**convergent + hybrid(含未分类)砸穿 → 直接平仓不重评**(`_direct_stop=tier in ("convergent","hybrid")`;收敛 8.3.0 从"交重评"改成直接平仓,hybrid 沿用 7.4.5);**event_driven → AUTO 8.1.0 起 −50% 强行直接平仓**(`_evaluate_position` 的 `(a2)` 分支,排在 $0.05 地板之后、其余止损线之前,任何东西越不过)。事件型的**盘中重评**改由"从最好点回撤 5pp"独立触发(§5.10),跟止损平仓是两条路。
- 确认计数器**在内存**(重启只延迟不误触);peak 持久化;`PENDING_REEVAL` 是持久后果态。

### 4.5 两条压舱石实现规则(不要改)

1. **触发价不对称 —— 止盈用 `best_bid`,止损用 `cur_price`**。止盈防"虚高"(cur 是最后成交价,低流动性上可能是远高于真实买价的孤单成交 → 按它卖锁的是假赢;best_bid = 真能卖进去的价,拿不到才退回 cur)。止损防"虚低"(做市商瞬间撤单时 bid 会瞬空 → 按 bid 卖在最差价;cur 给盘口恢复价差的时间)。TIME_STOP 和 edge 也用 cur。
2. **止损 / 止盈PnL 用 `pos.avg_price`,不用 `meta.entry_price`**。entry_price 是**首次**入场价,加仓/二次入场后不更新,用它会在再入仓上重复计盈。守卫 `avg = pos.get("avg_price") or entry or 0`。

### 4.6 平仓清档守卫

任何成功全卖 → `clear_position_meta(token_id)` 删整行。心跳还扫孤儿 meta(Polymarket 持仓 ⊃ db meta)。**关键守卫**:只在 `positions` **非空**时才扫 —— API 失败返回 `positions=[]` 绝不能清空所有 meta。部分卖出 / 失败卖出**永不**清档。

### 4.7 Edge 子状态(优先级 4)

| 子状态 | 条件 | 动作 |
|---|---|---|
| `HOLD` | edge > +2pp | 持有 |
| `MARGINAL` | −3pp ≤ edge ≤ +2pp | 观察 |
| `AT_TARGET` | edge < −3pp 且未重评 | 建议出场(执行前实时复核 cur≥q)|
| `SOFT_NEGATIVE` | edge < −3pp 且已重评 | 交重评 |

## 五、REEVAL 重评机制 —— 继承 + AUTO 自动化

### 5.1 触发时机

- **自动(分档,提前 5pp 触发)**:convergent −15%(锚 −20%)/ hybrid −30%(锚 −35%)/ event_driven 固定 −30% / 未分类 −20%(锚 −25%)。
- ~~**`PENDING_REEVAL` 防盲卖**~~(AUTO 8.3.0 **退役**):原"% 止损线砸穿 → 进 `PENDING_REEVAL` 交重评不盲卖"已废 —— 现在收敛/混合砸穿 + 事件 −50% **一律直接平仓**,没有砸穿→重评这条路了。`$0.05` 地板永远兜底。事件型的盘中重评改由"从最好点回撤 5pp"独立触发(§5.10)。

### 5.2 核心方法论 —— 盲评优先(4 段)

| 段 | 任务 | 能否看仓位信息 |
|---|---|---|
| A. 盲评 | 从零形成判断(Bull/Bear)| 🔒 否 |
| B. 24h 增量 | 微调 q | 🔒 否 |
| C. 对比 | 对比今日 q / 原 q / 入场 / 市场 | 是 |
| D. 决策 | hold / update_q / exit + IRR | 是 |

仓位块在 prompt 里被物理围栏(`🔒 [C 段前忽略]`)。

### 5.3 研究深度(按距结算)

| 距结算 | 盲评回看窗 | 总研究时长 |
|---|---|---|
| >60 天 | 60 天 + 全史 | 20–30 min |
| 30–60 天 | 30 天 + 关键史 | 15–25 min |
| 7–30 天 | 14 天 + 关键史 | 12–18 min |
| <7 天 | N×1.5 天(N=剩余天)| 8–12 min |

### 5.4~5.5 强制标注 + 规则注入

- **YES/NO 双向标注**:每个概率都标 `X% YES | Y% NO`(市场价/入场价/先验 q 全双标,`_to_yes_no`)。
- **Resolution 规则注入**:重评路从 Gamma 拉市场 `description` 把完整结算文本(1500+ 字)嵌进 prompt,模型不用自己找。

### 5.6 反锚定 —— "大跌前中枢"(v7.0 根因修)

老重评只喂被砸低的当前价 + 入场 + 先验 q + 新闻 → 模型锚在低价 → 给低 q → 微负 edge → 在底部建议 exit。修法 `_pre_dump_center(token_id, cur, hist)`:取尾部窗口,**剔除最后 `CENTER_SKIP_H`(默认 6h,砸盘段)**取中位数;数据不足或 `|center−cur|<0.01` 返回 None;**永不抛异常**。注入盲评块("大跌前价格中枢 —— 锚这个,不是当前价"),GLM 和 Claude 走同一 `_build_prompt` 自动一致。

### 5.7~5.8 输出结构 + 四决策

```
## 重评 YYYY-MM-DD
### A. 盲评   ### B. 24h 增量   ### C. 对比   ### D. 决策 [hold / update_q=X% / exit]
```

- `hold` 继续持有,止损不变。
- `update_q` 继续持有但更新 q(立刻按新 q + 现价重算 `monitor_state`,不等心跳)。
- `exit` 立即止损出场。
- ~~`cancel_autostop`~~ **已删**(AUTO 8.3.0 用户拍板):重评不能再"容忍继续亏、关本仓止损";已从 prompt/schema 移除,`_auto_execute` 即使收到也中和为 `hold`(不再置 `autostop_disabled`)。手动"止损OFF"开关暂留。

**event_driven exit 守卫已删**(AUTO 8.1.0, 2026-07-18 用户最高指令):原 `guard_event_driven_exit`(event_driven 的 `exit` 需 `thesis_broken` **或** `(new_q−cur) ≤ −0.08` 才准,否则降级 `update_q`,缺失/越界 → 默认 hold)在 `_auto_execute` + dashboard 确认路径**两处都删** → GLM 判 `exit` **立刻执行**。函数体保留但已无调用处(死代码)。⚠️ 方向纠错闸 `_confirm_new_q_direction`(镜像翻转反问 + exit 二次确认)**保留** = 仍防 GLM 把胜率数字填反卖错边。

### 5.9 在线 vs 离线执行

- **在线 = 暂停自动 API(退回手动贴 prompt,省钱);决策落 `pending` 等人确认**。在线永不盲卖:砸穿的仓进 `PENDING_REEVAL` + 红闪 manual 卡;卡闪超 `MANUAL_ESCALATE_MIN` 自动跑 API,**但结果仍是 pending 从不自动卖**。
- **离线 = 自动 API 接管 + 自动执行决策(真钱)**:`_auto_execute` —— exit → 重拉实仓 + `Executor.sell` + 记 `closed_positions` + 清 meta;update_q → 应用 + 重算态;~~cancel_autostop → 置旗~~(8.3.0 已删,中和为 hold);hold → 空操作。
- **本项目 `AUTO_FORCE_OFFLINE=1` 永远离线** —— 重评决策自动执行,开页面看盘不暂停自动化。`force_manual=True` 永远等手动。

### 5.10 重评触发/节流(AUTO 8.3.0 重写)

**盘中"亏损触发重评"只对 event_driven**(收敛/混合的止损=直接平仓,不盘中重评;**每天 15:00 全仓巡检重评对所有仓照旧**,是独立一路,不受此影响)。event_driven 规则:
1. **inflight 锁**(`has_inflight_auto_reeval`=analyzing/pending/manual)—— 永不双 launch(用 `has_inflight` 不是 `has_active`)。
2. **从"持有期最好点"回撤 ≥5pp 触发 1 次**(`AUTO_REEVAL_RETRIGGER_DROP` 默认 0.05,任何盈亏水平):基线 = 上次触发后见过的**最低 `loss_pct`**(创新低/涨回去 → 基线下移);`loss_pct ≥ 基线 + 0.05` → 触发并把基线重置到当前 → **单次暴跌只算 1 次**(不按 5pp 整除);40%→涨回 35%→再跌 40% 会再触发。**无时间冷却**(旧的 6h 冷却 + 首拍记基线 + 10pp 门槛已废)。手动 🤖 触发绕过。

### 5.11 多模型 —— GLM 主用 + Claude 兜底

- 编排 `run_auto_reeval` 按 `_provider_order()`(默认 `['glm','claude']`,只用有 key 的;`AUTO_REEVAL_PRIMARY` 可翻)。第一个返回**合法决策**(action∈四选一)的胜出,打 `_provider` 标。
- **GLM 路** `_run_glm`:`glm-5.2`(1M 上下文/128K 输出)、思考开 + `reasoning_effort=max`、原生 `search_pro`(count=20,content_size=high)、`max_tokens=120000`、client 超时 1200s。**解析硬化** `_glm_regex_extract`:先严 `json.loads`,失败按已知 schema 正则抠字段(GLM 常在中文自由文本里塞未转义 `"` 破坏严格 JSON)—— **别删这个正则兜底**。
- **防线**:GLM 必须返回严校验的合法决策或报错/抛异常 —— 半成品/越界 q/非法 action **绝不能**进 `_auto_execute`。Claude 是可靠兜底 + prompt 契约基准,别动 `_run_claude`。
- 决策 dict 字段跨 provider 完全一致:`action / new_q(0–1 持有方向概率)/ confidence / thesis_broken(仅标记非决策前提)/ headline_event / reason / sources`。

### 5.12 反向推荐触发重评(2026-07-10)

见第三章 `_trigger_reverse_reeval`:选品给出已持仓位的反方向 → 挡对锁 + 立刻对该持仓触发正规重评(理由注入 prompt),inflight 互斥 + 6h 去重。走现有管道(方向纠错闸 + 离线自动执行)。

## 六、DISCOVERY 选品方法论 —— 继承

### 6.1 每个候选模型必须产出

1. Bull / Bear 各 1–2 个权威信源
2. 原始估计 `raw`
3. **校准** = `market_price + 0.5×(raw − market_price)`(向市场半收缩)
4. 校准 Edge = `校准 − cur`
5. 执行成本 = taker 滑点 + 双边各 2.2pp
6. **真实可得 Edge** = 校准 edge − 执行成本

### 6.2 推荐门槛(校准 edge)+ 价格区间不对称

| 模式 | 校准 edge 门槛 | 价格带 |
|---|---|---|
| 标准 standard | ≥ 8pp | 8%–92% |
| 中 medium | ≥ 11pp | 5%–95% |
| 大 wide | ≥ 14pp | 3%–97% |

低端故意更宽:**<15% 是冷门反向操作的甜区**。(注:全自动链路写死只用 **medium**。)

### 6.3 年化 IRR

`IRR = (校准 − p)/p × 365/天 × 100%`,`<30%` 不推 / `30–100%` 可接受 / `>100%` 甜区。

### 6.4~6.5 止损档分类 + cluster 注入 + 语言锁

- 模型按结算标准把每候选分 `convergent`/`hybrid`/`event_driven`(驱动第四章止损)。
- 现有 cluster 字典自动前置到 prompt(复用已有 `cluster_id` 不造近义词,否则破 cluster cap)。
- 末尾输出机器可读 JSON:`slug/side/cur_price/q/confidence/stop_loss_tier/end_date/days_to_resolution/cluster_id/tag/reason`(字段名是契约)。
- "语言锁"段强制简体中文输出(Deep Research 默认英文)。

## 十、Sizing 仓位公式 —— 继承(`position_size_usd()`)

真买金额 = 这个计算器,5 步单层折扣:

```
1. Edge 检查:  edge = q − p;edge ≤ 0 → $0("无 edge")
2. 单 token Kelly:
               kelly_f = edge / (1 − p)
               raw = bankroll × kelly_f × 0.25             # 1/4 Kelly
3. 天数 + 冷门调整:
               days_factor  = sqrt(21/days),clip [0.40, 1.0]
               longshot_mult = 1.0            当 p ≥ 0.15
                               0.5 + 0.5×(p/0.15)  否则
4. cluster + 月DD预算 取小:
               cluster_room = cluster_cap − cluster_当前敞口
               dd_cap       = (30 − 组合已暴露DD) / TIER_DD[tier]
5. 硬边界:     clip 到 [$1, $15]
```

- **Bankroll** = `cash + Σ(cur_price × size)`。
- **cluster cap** = `SIZING_CLUSTER_CAP_PCT(0.20) × bankroll`。
- **现价口径(关键)**:`cluster_exposure` 和 `组合已暴露DD` 都用 **`cur_price × size`** 不用成本价 —— 否则敞口指标跟(现价口径的)bankroll 自相矛盾,会漏算已满的 cluster 而错误推荐第 N 个相关仓。
- **单层折扣**:DISCOVERY 已把 `q' = p + 0.5×(q_raw − p)`;公式**不再**二次折扣(总信任保持 0.5);`confidence` 收到但不用。
- `TIER_DD`(回撤权重):`convergent 0.20 / hybrid 0.35 / event_driven 0.70`。
- **cluster 命名** `<主题>-<方向>`,按**相关性**分组不按主题:"这仓赢了哪些会一起赢?"→ 同 cluster;同主题**反方向** = 反相关 → 不同 cluster。
- env:`SIZING_KELLY_FRACTION=0.25 / SIZING_CLUSTER_CAP_PCT=0.20 / SIZING_MONTHLY_DD_BUDGET=30.0 / SIZING_MAX_SINGLE_POS=15.0 / SIZING_MIN_SINGLE_POS=1.0 / SIZING_REF_DAYS=21.0 / SIZING_LONGSHOT_THRESH=0.15`。

## 十四、智谱 GLM 并发实测结论(2026-07-08/09)
